Jinx API

Anime episodes, metadata, schedules and streams, normalized into one clean JSON API. Pure JavaScript scraping layer, signed HLS media proxy, ready for Vercel.

Self-hosted and Vercel-ready service that scrapes anikototv.to for catalog metadata, episode lists and stream tokens, then normalizes everything into one fast JSON API with playable HLS playlists, subtitles and skip times. No API key, no npm dependencies.

Introduction

Everything the source site exposes is here as clean JSON, built for direct use in a front end. You can ship a full anime streaming experience with plain fetch.

  • Metadata. Titles in English and Japanese, synopsis, genres, studios, scores, ratings, seasons and related series.
  • Episodes and servers. Full episode lists with sub/dub flags, then every streaming server available per episode.
  • Streaming. HLS master playlists with quality variants, multi language subtitles and skip intro/outro times.
  • Discovery. Home page rails, search, advanced filters, A to Z listing, genres, weekly schedule and random picks.

This project is for educational purposes. All anime content, names and media belong to their respective owners. Respect the source site and keep request volume reasonable.

Quick start

Run it locally or deploy it, then call any endpoint. Everything is plain GET requests returning JSON.

git clone <your repo> jinx
cd jinx
npm start
# local server at http://localhost:8787

First live call:

curl "http://localhost:8787/api/search?q=naruto"
{
  "ok": true,
  "data": {
    "query": "naruto",
    "results": [
      {
        "slug": "naruto-eybxz",
        "title": "Naruto",
        "titleJp": "Naruto",
        "poster": "https://cdn.anipixcdn.co/thumbnail/71a3cb....jpg",
        "type": "TV",
        "score": "7.89",
        "rating": "PG-13"
      }
    ]
  }
}

API index lives at https://YOUR-DEPLOYMENT/api — docs at / — health at /api/health.

Deploy on Vercel

1. Push the project to a Git repository

GitHub, GitLab or Bitbucket. The repo root must contain the api folder and vercel.json.

2. Import it on Vercel

Open vercel.com/new, import the repo and keep every build setting on auto. Vercel detects the api folder on its own.

npx vercel --prod
# routes / -> api/index.js, every /api/* path becomes a function

3. Deploy and point your web at it

You get a URL like https://jinx.vercel.app. Opening it shows this docs page. Every endpoint sends Access-Control-Allow-Origin: *, so a browser app on any domain can call them directly.

Response format

Every endpoint returns the same envelope. Success responses carry ok: true and a data object. Failures carry ok: false and a human readable error string, with a matching HTTP status code.

// success
{ "ok": true, "data": { /* payload */ } }

// failure
{ "ok": false, "error": "Missing query parameter q" }

A typical item object inside lists looks like this. Fields that do not apply to a title arrive as null so the shape stays predictable:

{
  "id": "9054",
  "slug": "a-tale-of-the-secret-saint-7aebe",
  "episode": "6",
  "title": "A Tale of the Secret Saint",
  "titleJp": "Tensei shita Daiseijo wa, ...",
  "poster": "https://cdn.anipixcdn.co/thumbnail/4ed8034d....jpg",
  "episodes": { "sub": "6" },
  "type": "TV",
  "score": "7.5",
  "rating": "PG-13"
}

API Reference

Sixteen endpoints cover everything the source exposes. All of them accept only GET requests.

GET/api/home

The full home page. Spotlight slider, latest episodes, trending, new releases, newly added, just completed and the top anime charts for day, week and month.

No parameters.

curl "https://YOUR-API/api/home"
{
  "ok": true,
  "data": {
    "spotlight": [ { "rank": "#1 Spotlight", "slug": "black-clover-season-2", ... } ],
    "latestEpisodes": [ { "slug": "a-tale-of-the-secret-saint-7aebe", "episode": "6", ... } ],
    "trending": [ ... ],
    "newRelease": [ ... ],
    "newAdded": [ ... ],
    "completed": [ ... ],
    "topAnime": {
      "day":   [ ... ],
      "week":  [ ... ],
      "month": [ ... ]
    }
  }
}

GET/api/filter

Advanced browsing with the full filter set. Combine as many parameters as you like. List parameters accept comma separated values, and a negative genre id excludes that genre.

ParameterDescription
keywordFree text title search.
genreGenre ids or slugs, comma separated. Prefix an id with - to exclude it.
typeTV, Movie, OVA, ONA, Special, Music, TV_SHORT.
seasonspring, summer, fall, winter.
yearFour digit year or list of years.
statusfinished-airing, currently-airing, not-yet-aired.
languagesub or dub.
ratingG, PG, PG-13, R, R+, Rx.
sourcemanga, original, light_novel, novel, visual_novel, and others.
ep_min / ep_maxEpisode count range.
sortdefault, latest-updated, latest-added, score, name-az, release-date, most-viewed, number_of_episodes.
pagePage number, 30 titles per page.
curl "https://YOUR-API/api/filter?type=TV&status=currently-airing&sort=score&page=1"
{
  "ok": true,
  "data": {
    "items": [ /* title cards */ ],
    "pagination": { "page": 1, "totalPages": 12, "hasPrev": false, "hasNext": true }
  }
}

GET/api/stream

The heart of the API. Resolves a playable stream with quality variants, subtitles and skip times. There are three ways to call it, from simple to granular.

ParameterDescription
slug + episoderequired*The show slug and the episode number or slug. Simplest form.
idsaltAn episode ids value. Skips the episode list lookup.
linkaltA linkId from the servers endpoint. Lowest level.
serverOptional server picker, matches svId or the name like HD-1. Defaults to the first one.
typeOptional audio filter, sub or dub.
curl "https://YOUR-API/api/stream?slug=the-elusive-samurai-season-2-359bc&episode=12"
{
  "ok": true,
  "data": {
    "episode": { "number": "12", "sub": true, "dub": false },
    "server": { "name": "HD-1", "svId": "323", "type": "sub" },
    "embed": "https://megaplay.buzz/stream/s-2/236994/sub?s=tcdn",
    "player": { "id": "180084", "cdn": "tcdn", "label": 4 },
    "thumbnail": "https://de3bv.eclipseharbor.world/.../thumbnail.jpg",
    "skip": {
      "intro": { "start": 0, "end": 128 },
      "outro": { "start": 1322, "end": 1417 }
    },
    "master": {
      "file": "https://megap.shiora.top/.../master.m3u8",
      "proxy": "https://YOUR-API/api/proxy?u=https%3A%2F%2F..."
    },
    "sources": [
      { "quality": "1080p", "resolution": "1920x1080", "bandwidth": 5500000,
        "file": "https://megap.shiora.top/.../index-f1.m3u8",
        "proxy": "https://YOUR-API/api/proxy?u=..." },
      { "quality": "720p", "resolution": "1280x720", "bandwidth": 2800000, ... },
      { "quality": "480p", "resolution": "640x360", "bandwidth": 800000, ... }
    ],
    "subtitles": [
      { "label": "English", "kind": "captions", "default": true,
        "file": "https://de3bv.eclipseharbor.world/.../track_0_eng.vtt",
        "proxy": "https://YOUR-API/api/proxy?u=..." },
      { "label": "Arabic", "kind": "captions", ... }
    ]
  }
}

Each stream URL comes in two flavors. file is the raw CDN link and proxy is the same link routed through /api/proxy, carrying a signature. The CDN blocks hotlinking, so players should load the proxy URLs as they are. Every proxy URL returned here is signed and ready to use.

GET/api/proxy

Small media proxy that forwards requests to the streaming CDN with the correct headers. It also rewrites m3u8 playlists so every segment and subtitle stays inside the proxy. This is what makes in browser playback possible.

ParameterDescription
urequiredThe full https CDN URL to proxy.
srequiredSignature generated by the API. Every proxy URL from /api/stream already carries one, so you never build these links by hand.
curl "https://YOUR-API/api/proxy?u=https%3A%2F%2Fmegap.shiora.top%2F...%2Fmaster.m3u8&s=AsV7ZyyTe9vOA3Iqt8Plng..."

GET/api/refresh

Warms the hot feeds (home, latest, schedule) so new episodes surface within moments of airing. Called automatically by the auto update layer, but you can trigger it yourself after major schedule changes.

curl "https://YOUR-API/api/refresh"
{
  "ok": true,
  "data": {
    "warmed": [
      { "feed": "home", "ok": true },
      { "feed": "latest", "ok": true },
      { "feed": "schedule", "ok": true }
    ],
    "time": "2026-01-01T12:00:00.000Z"
  }
}

Hands off. On Vercel a cron calls this every day (Hobby friendly) and the short TTL caches revalidate on demand; when self hosting, the bundled server warms the feeds every sixty seconds. See Auto updates.

GET/api/health

Uptime and version check.

curl "https://YOUR-API/api/health"

Integration guide

Follow these steps to build a working streaming web app. Each step is a single call. Replace API with your deployment URL.

1. Set your base URL once

Keep one constant in your front end so you can move between local and production with one edit.

const API = "https://YOUR-API";

2. Fill the home screen

Use /api/home to render the spotlight slider, the latest episode grid and the top charts in one round trip.

const home = await fetch(`${API}/api/home`).then(r => r.json());
renderSpotlight(home.data.spotlight);
renderGrid(home.data.latestEpisodes);

3. Let users search

Call /api/search on each keystroke, with a small debounce. The result cards carry everything you need for a suggestion dropdown.

async function search(q) {
  const res = await fetch(`${API}/api/search?q=${encodeURIComponent(q)}`).then(r => r.json());
  return res.data.results;
}

4. Build the detail page

When a title is picked, call /api/anime/:slug and /api/episodes/:slug together.

const slug = "the-elusive-samurai-season-2-359bc";
const [info, eps] = await Promise.all([
  fetch(`${API}/api/anime/${slug}`).then(r => r.json()),
  fetch(`${API}/api/episodes/${slug}`).then(r => r.json()),
]);
console.log(info.data.title, info.data.synopsis, eps.data.episodes.length);

5. Resolve a stream when the user presses play

One call gives you the playlist, every quality variant, subtitles and skip markers.

const stream = await fetch(
  `${API}/api/stream?slug=${slug}&episode=12`
).then(r => r.json());

const master = stream.data.master.proxy;   // play this
const skip = stream.data.skip;             // skip intro and outro

6. Offer server choice and downloads

Use /api/servers so the user can switch between HD, Vidstream and others, then pass the chosen linkId to /api/stream?link=. Use /api/downloads for an offline download menu.

const servers = await fetch(`${API}/api/servers?ids=${ep.ids}`).then(r => r.json());
const stream = await fetch(`${API}/api/stream?link=${servers.data.groups[0].servers[1].linkId}`).then(r => r.json());

Custom player

Jinx ships with a full watch page built on this API, styled after the source site. It lives at /player and needs zero setup.

https://YOUR-DEPLOYMENT/player                      // start with search
https://YOUR-DEPLOYMENT/player?slug=one-piece-1999  // open a series
https://YOUR-DEPLOYMENT/player?slug=one-piece-1999&ep=12&type=dub

What it does

Player chrome modeled on modern streaming apps: floating control pills with play, volume and time, ten second rewind and forward, next episode, download links from /api/downloads, screenshot capture, picture in picture and fullscreen. The settings panel opens submenus for play speed, quality, subtitles, subtitle size, subtitle timing, subtitle quality, volume boost and audio track selection. Skip intro and outro buttons appear exactly when the markers say so. Episode grid with SUB/DUB filtering, server chips for switching mirrors, resume position and watched marks that persist in the browser, plus auto play, auto skip and auto next toggles.

Keyboard shortcuts

Space or K play and pause, J/L jump ten seconds, arrows seek five seconds, M mute, F fullscreen, double click the video for fullscreen.

Point it at any Jinx host

The player calls the API it is served from. To run the page somewhere else and still use your deployment, add ?api= once and it is remembered.

/player?api=https://jinx.vercel.app&slug=one-piece-1999

Build your own? The player is a single HTML file, docs/player.html. Fork it, restyle it, or use it as the reference for the integration steps above.

Auto updates

Jinx fetches new content the moment the source publishes it. A small freshness layer keeps every feed current without hammering the site.

How it works

Every endpoint sits on a short lived cache with stale while revalidate semantics. When a cached answer expires, the next request gets the fresh copy while the old one is served in the background. The hot feeds (home, latest, schedule) are also warmed proactively on a timer.

Timers

FeedCache
/api/search30 seconds
/api/home, /api/latest60 seconds
/api/schedule, /api/episodes, /api/filter, /api/az.list, /api/browse2 minutes
/api/servers5 minutes
/api/anime, /api/downloads10 minutes
/api/stream, /api/randomnever cached

Warming

Self hosting with node local.js refreshes the hot feeds every sixty seconds. On Vercel, the vercel.json cron calls /api/refresh once a day (Hobby plans only allow daily crons) and every request revalidates on demand through the TTL caches above, so a brand new episode is served within a minute of the next request.

// force a warm right now
fetch("https://YOUR-API/api/refresh")

Player setup

Streams are HLS, so use HLS.js in browsers without native HLS support. Always load the proxy URL and the CDN will accept the request.

<video id="player" controls width="100%"></video>
<script src="https://cdn.jsdelivr.net/npm/hls.js@latest"></script>
<script>
  const video = document.getElementById("player");
  const playlist = stream.data.master.proxy;

  if (Hls.isSupported()) {
    const hls = new Hls();
    hls.loadSource(playlist);
    hls.attachMedia(video);
    hls.on(Hls.Events.MANIFEST_PARSED, () => video.play());
  } else {
    video.src = playlist;
  }

  // optional: skip intro and outro
  video.addEventListener("timeupdate", () => {
    const intro = stream.data.skip.intro;
    if (intro && video.currentTime > intro.start && video.currentTime < intro.end) {
      video.currentTime = intro.end;
    }
  });
</script>

Subtitles work with HLS.js subtitle tracks or with a manual <track> element pointing at subtitles[n].proxy:

for (const sub of stream.data.subtitles) {
  const track = document.createElement("track");
  track.kind = "subtitles";
  track.label = sub.label;
  track.src = sub.proxy;
  video.appendChild(track);
}

Error handling

Check the ok field first. A robust client looks like this:

async function call(path) {
  const res = await fetch(`${API}${path}`);
  const body = await res.json();
  if (!body.ok) throw new Error(body.error);
  return body.data;
}
StatusMeaning
200Success, ok: true.
400Missing or invalid parameter. The error text names the fix.
403The proxy URL is unsigned or tampered with. Use the links from /api/stream.
404Unknown slug, episode or server.
500+The source site failed or changed. Retry once, then surface the message.

FAQ

Do I need an API key?

No. Every endpoint is open and CORS enabled.

Why does playback need the proxy?

The video CDN checks the request origin and blocks hotlinks. /api/proxy forwards the media with valid headers and rewrites playlists on the fly.

Can I use this on mobile apps?

Yes. The proxy URLs are plain HLS playlists that ExoPlayer, AVPlayer and hls.js all understand.

How much can I cache?

All GET responses already send Cache-Control with short freshness windows tuned per endpoint (see Auto updates). Cache aggressively on your side too.

The stream returned no sources.

That episode is very new or the server rotated. Try another server via /api/servers or retry in a minute.

Is there a rate limit?

None is enforced, but stay under a few requests per second so the source stays healthy for everyone.
